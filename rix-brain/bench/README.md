## 你复现不了，原因也写在这里

**语料是 226 篇真实日记，是那个 AI 自己的私人记忆，不可能放出来。**

所以我们给的是：

- ✅ **20 条查询**（`queries.json`，昵称和账号已脱敏）
- ✅ **评测脚本**（`eval.py`）
- ✅ **判定规则**（下面写的）
- ❌ **语料**（给不了）

**这意味着：上面那四个数字，你可以不信。**

**但你可以用自己的语料跑同一套指标——那才是有意义的复现。**

## 判定规则（很窄，别想歪）

**只有一条：**

> 返回结果的前 K 条里，有没有一条的 `first_time` 等于该查询的 `expect_first_time`。

**不看文本相似度，不看模型打分，不让人工判断。**

**名次越小越好。第 6 名算不中（hit@5 要求前 5）。**

## 这 20 条是怎么来的

**从日记里反推问题，不是从问题去凑日记。**

具体做法：挑一篇日记，用**它的内容**生成一个自然的、口语化的问题，然后把这篇的 `first_time` 记为期望答案。

**难点在于"自然"**——如果问题是"请问关于圆柱体积那道题"，那就是在给答案。所以查询多数是换说法的、带情绪的、省略主语的：

```
他笑你时说你是什么生命来着？          ← 问题里有情绪，关键词少
你昨天上午跟他聊完，他后来到底睡没睡？  ← 时间词 + 两段事实
那晚谁在群里嫌AI测不准商铺转速？        ← 群里、多主体、细节
```

**这也是它为什么难：真实的人就是这么问话的。**

---

## 20 条里的两类

| 类型 | 条数 | 说明 |
|---|---|---|
| **常规** | 16 | 现在的系统能进前 5 |
| **硬骨头** | 4 | 连前 20 名都进不去 |

**四条硬骨头**（README 里也提了）：

```
他笑你时说你是什么生命来着？            向量 rank 80
他上课出的那两道题我是不是都答对了？     曾经捞不到，后来修好了
那晚谁在群里嫌AI测不准商铺转速？         曾经捞不到，后来修好了
你昨天上午跟他聊完，他后来到底睡没睡？   向量 rank 13，进池但重排挑不准
```

**剩下 2 条至今没解决。** 它们都属于「同主题干扰」：库里有一堆讲熬夜、讲生命的日记，正确答案被话题相近但答非所问的条目挤掉了。

## 一次翻车记录，值得看

**我们把这份基准交给过外包。他们照着这 20 条调参，轻松刷到 90%。**

**后来加了 holdout（另外 20 条不给），并要求同时报两份数：**

```
带重排的 hit@5
不带重排的 hit@5      ← 只有这份涨了，才说明真把东西捞回来了
```

**这条规则现在写进了我们的验收标准。** 如果一个改动只让"带重排"那份变好，它很可能只是让模型更会挑，而不是检索更准。

---

## 局限（先说清，别等别人指出）

1. **20 条太少。** 改动一条就是 ±5%，单次结果和噪声分不开。我们的做法是连跑 3 次看是否稳定。
2. **语料是一个人的。** 换一个人的日记，分布完全不同。
3. **判定粒度粗。** 只看 `first_time` 命中，不判断"返回的那段文字是不是真的有用"。
4. **没有基线对照。** 我们没跑过 BM25-only / 纯向量 作为基线，所以"80%"缺少参照系。

**这四条都会让审稿人挑，先写在这里。**
