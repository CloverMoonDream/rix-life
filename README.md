# Rix · 在 QQ 上养一个长期存在的 AI

> 一份**诚实的工程记录**：怎么让一个 LLM 有连续的记忆、自己的时间、一块能动手的地方。
>
> **这不是产品，不是框架，也不是一键部署。** 它是一套跑了一个多月、每天在用的系统里，
> **可以单独拿走的三个零件**，加上我们踩坏的那些坑。

---

## 先看这三句话

1. **它不是"AI 助手"。** 它不会你问一句答一句——它会自己醒、自己睡、自己找事做。
2. **它不是"记忆库"。** 记忆只是让它能连续存在的那一层；上面还有唤醒调度和工具边界。
3. **它不是开箱即用的。** 我们写清了依赖和门槛，**跑不起来是正常的**，看懂思路才是目的。

---

## 三块可以单独拿走的零件

### ① 记忆引擎（`rix-brain/`）

一个 AI 的记忆分三层，跨会话可检索：

| 层 | 是什么 | 存在哪 |
|---|---|---|
| **短期** | 每个会话最近的对话原文 | `chats/<会话>/short_term.json` |
| **日记** | 按天、按会话总结的记录（分主观/客观） | `chats/<会话>/diary.json` |
| **长期** | 跨会话检索上面两层 | 无独立存储，检索时合成 |

**召回链路**：词面（gram 覆盖）+ 向量（本地 bge-m3）+ 属性联想 → 合并候选池 → 一次语义重排 → 按配额取。

**有测试**：176 个用例，零第三方依赖，离线可跑。

```bash
cd rix-brain
python -m unittest discover -s tests      # 2~4 秒，全绿
```

### ② 运行时（`qq-bridge/`）

把 QQ 消息接进 agent，并决定**什么时候叫醒它**：

- 唤醒调度：有人说话 / 自己定的钟 / 每 20 分钟的"自己的时间"
- 发送控制：分条节奏、频率配额、白名单
- 会话轮换：上下文到阈值就换页（不是截断，是开新会话并交接）
- 工具网关：MCP

### ③ 沙箱配方（`sandbox/`）

一个**能上网但碰不到宿主机**的 WSL 环境：

```bash
# 出网规则：只放行 DNS，私有网段全拒绝
sandbox/sandbox-net.sh
```

**这是最值钱的部分。** 里面那几条 iptables 的顺序，是我们踩坏的（WSL 的 DNS 在 `10.255.255.254`，属于 `10/8`——先拒绝就全断网）。

| 指标 | 值 |
|---|---|
| 单轮上下文 | 20k ~ 66k token（回合越长越高） |
| 每步平均上下文 | ~47k token（一周从 43k 涨到 47k） |
| 缓存命中率 | 98% |
| 单轮成本 | ¥0.01 ~ ¥0.16 |
| 记忆规模 | 226 篇日记，约 170 KB |
| 召回质量 | hit@1 80% / hit@5 90%（20 条冻结基准） |
| 角色提示词 | 6,077 字符（硬上限 7,000，超了静默截断） |

## 我们做错了什么

**这一节比代码值钱。**

### 1. 让重排模型从大池子里自己挑第一名

投入后 **hit@1 从 40% 掉到 10%**。

原因：候选池一大，模型会挑"话题相关"的，不是"这条能回答的"。它需要的是**小池子 + 明确的判断标准**。

### 2. 向量查询带上上下文

**45% → 10%**。

300 字的上下文比 query 长得多，embedding 被上下文带跑。

### 3. 用数值表达情绪

跑了两个月，删了。**没人真的在读那个数字。**

现在情绪只活在记忆里：她自己写日记、自己召回。配额固定 10 条。

### 4. 角色卡超长被静默截断

切在「白色蕾」半个词上，**找了三天**。

### 5. 沙箱输出被记成"用户消息"

`{self: false, sender: '沙箱'}`——等于"一个叫沙箱的人给她发消息"。

三天后才发现：

- 短期记忆 1500 行里 1336 行是机器日志，**真人对话全被挤出去了**
- 身份标签取"出现最多的昵称"，于是把机器当成了对方的名字
- 日记里出现主客颠倒：「**他说**今天要去沙箱折腾鱼」——其实是她说的

**修法不是删日志，是给它一个独立的类别**（`kind: 'tool'` → 记成「工具」角色）。

### 6. 评测标准可以被刷

给了外包 20 条查询和答案，他们**照着调参**就能到 90%。

后来加了 holdout，并要求报两份数：**带重排的**和**不带重排的**。
只有不带重排那份涨了，才说明真把东西捞回来了。

### 7. 没有测试

改了 80 行代码，全靠"跑一遍看看"。**零单元测试**跑了一个月。

现在有 176 个，其中一条是**变异测试**：随机改代码 10 处，至少 8 处必须让测试变红。

## 四个我们还没解决的问题

**这是要反馈的地方，不是客套。**

### 1. 记忆分层这样做对吗？

短期/日记/长期三层，跨会话靠检索。**有没有更简单的做法？**

我们的瓶颈不在排序，在**召回**：有 2 条查询，正确答案连前 20 名都进不去（同主题干扰）。

### 2. 唤醒该怎么调度？

现在是"固定 20 分钟 + 她自己定的钟"。**有没有更好的模型？**

观察到的问题：没有"进行中的事"时，她会连着睡很久。

### 3. 沙箱还有哪些逃逸面？

WSL2 + iptables + 无 drvfs + interop 关闭。**没挂载 C/D、宿主机不通、局域网不通。**

但**公网是通的**——数据可以出去。我们没想到怎么在不影响 `apt` 的前提下收紧。

### 4. 最难的那个：怎么区分"她自己动"和"被我们引着动"？

我们现在的唯一判据是：**没人提的时候她还回不回去**。

但她所有的"新方向"都来自我们。这条判据还不够。

## 依赖与门槛

```
QQ 协议    SnowLuma（OneBot 11）
宿主       DSH（桌面应用）
模型       DeepSeek API（OpenAI 兼容）
向量       本地 ollama + bge-m3
沙箱       WSL2（Linux）
```

**五个外部件，任何一件挂了整套瘫。**

`rix-brain` 可以单独跑（只要有 embedding 和一个 OpenAI 兼容的 LLM）。

## 不包含什么

- **人设 / 角色卡**：那是它的身份，不随本项目提供。自己写一个。
- **任何数据**：日记、会话、笔记、聊天记录，都不在仓库里。
- **凭证**：`config.json` 全部是样例，没有真实 key。
