# 部署教程：每一步在干什么

> 这份文档假设你**从零开始**，目标是把整套东西跑起来。
>
> 每一步都写三件事：**做什么 / 为什么有这一步 / 怎么确认它成了**。
>
> **先说清楚**：这不是一键部署。五个外部件、每一个都要装。预计 3~6 小时（第一次）。

---

## 总览：数据怎么流

```
        ┌──────────┐
        │   QQ     │  你/群友发消息
        └────┬─────┘
             │  WebSocket / HTTP
        ┌────▼──────────┐
        │ SnowLuma      │  第 5 步：把 QQ 协议翻译成 OneBot 11
        └────┬──────────┘
             │  OneBot 11
        ┌────▼──────────┐
        │ qq-bridge     │  第 6 步：什么时候叫醒它、怎么发回去
        │  (Node)       │         ├─ 唤醒调度
        └────┬──────────┘         ├─ 分条/配额
             │  HTTP + 事件流      └─ 记忆接线
        ┌────▼──────────┐
        │ DSH           │  第 4 步：agent 宿主（调模型、跑工具循环）
        └────┬──────────┘
             │ MCP
        ┌────▼──────────┐
        │ rix-brain     │  第 3 步：三层记忆 + 召回
        │  (Python)     │
        └────┬──────────┘
             │
      ┌──────┴──────┐
      ▼             ▼
  ollama        沙箱（WSL）      第 2 步：它能动手的地方
  bge-m3
```

**记住一条**：**记忆在 Python 那边，唤醒在 Node 那边，模型在 DSH 那边。**
三件事分开，任何一件坏了，其余两件还能单独测。

---

## 第 0 步：确认你要的是什么

**这套东西解决的是「让一个 AI 连续存在」**，不是"接个 QQ 机器人"。

**如果你只想让 AI 在群里回话** → 用原版 [qq-bridge](https://github.com/Derpyu520/qq-bridge)，别装这套。

---

## 第 1 步：前置检查

**做什么**

```powershell
# Windows 10/11，管理员 PowerShell
wsl --version          # 需要 WSL2
node --version         # 需要 >= 22.13
python --version       # 需要 >= 3.10
ollama --version       # 向量用
```

**为什么**
后面四件东西各依赖一个：WSL 给沙箱，Node 给桥接，Python 给记忆，ollama 给向量。

**怎么确认**
四条命令都有版本号输出。缺哪个先装哪个——**这一步不建议跳过**，后面报错都很难定位。

---

## 第 2 步：沙箱（WSL）

**做什么**

```powershell
wsl --install -d Ubuntu
wsl --manage Ubuntu --resize 20GB       # 默认上限是 1TB，先压住
```

进入 Ubuntu 后：

```bash
sudo apt update && sudo apt install -y python3 iptables curl
sudo bash sandbox/sandbox-net.sh        # 出网规则
```

**为什么**
agent 需要一个**能随便搞坏、但碰不到你的电脑**的地方。

`sandbox-net.sh` 干的事：只放行 DNS，**私有网段（10/8、172.16/12、192.168/16）全部 REJECT**。

**这里有个坑，我们踩过**：WSL 的 DNS 在 `10.255.255.254`，**属于 10/8**。
所以必须先放行 DNS 再拒绝 10/8——**顺序反了，整个沙箱断网，而且报错很像"没网"**。

**怎么确认**

```bash
# 在 WSL 里
curl -s -o /dev/null -w "%{http_code}\n" https://www.baidu.com    # 应该 200
curl -s -o /dev/null -w "%{http_code}\n" http://<你的宿主机IP>:3100 # 应该 000
```

**一个 200、一个 000，就对了。**

## 第 3 步：记忆引擎（rix-brain）

**做什么**

```powershell
# 本机（不是 WSL 里）
ollama pull bge-m3
cd rix-brain
copy config.example.json config.json
# 编辑 config.json：填 deepseek.api_key
python -m unittest discover -s tests
```

**为什么**
这是整套东西里**唯一不依赖 QQ 的部分**。先把这块跑通，你就有了一个能记住东西的引擎，
后面接不接 QQ 都能单独用。

`bge-m3` 负责把中文变成向量（1024 维），**不联网、不花钱**。

**怎么确认**

```bash
python -m unittest discover -s tests     # 176 个，全绿，2~4 秒
```

**测试全绿 = 记忆层能用了。** 这一步不过，别往下走。

---

## 第 4 步：宿主（DSH）

**做什么**

装 DSH（DeepSeek Harness），起一个会话，确认能正常对话。

**为什么**
DSH 是**跑 agent 循环的地方**：它调模型、解析工具调用、管理上下文。
我们的桥接不自己调模型——它只负责"什么时候叫醒"，模型调用交给 DSH。

**怎么确认**

```powershell
# DSH 起来后，它会监听一个本地端口（每次重启都变）
# 桥接用 dsh-client.js 去发现它
```

**注意**：**DSH 是桌面应用，端口每次都变。** 我们的适配层会自动发现，
但如果你自己写 agent 循环，别把这个端口写死。

---

## 第 5 步：QQ 协议（SnowLuma）

**做什么**

装 SnowLuma（OneBot 11 网关），登录你的 QQ 小号。

**为什么**
QQ 的协议是逆向的，自己实现要处理登录、加密、心跳、风控——**这不是一天的事**。
SnowLuma 把它翻译成标准的 OneBot 11，桥接只跟标准协议打交道。

**怎么确认**

```
ws://127.0.0.1:3001 能连上，发 get_login_info 能返回你的号
```

---

## 第 6 步：桥接（qq-bridge）

**做什么**

```powershell
cd qq-bridge
npm install
copy config.example.json config.json
# 编辑：填 SnowLuma 的 ws 地址、你的 QQ 号（白名单）、模式
node src/bridge.js
```

**为什么**
它决定**什么时候叫醒 agent**，以及**回复怎么发出去**。具体改了什么见 `MODIFICATIONS.md`。

**关键配置**

| 配置 | 干什么 | 建议 |
|---|---|---|
| `ownerQQ` | 谁是主人 | 填你自己的号 |
| `allow.groups` | 哪些群能用 | 先只填一个测试群 |
| `socialV2.selfTime.intervalMs` | 自己醒的间隔 | 20 分钟起，别太短 |
| `socialV2.session.rotateAboveTokens` | 换页阈值 | 60000 |

**怎么确认**

```
日志里出现：
  SnowLuma 已连接：ws://...
  机器人昵称: xxx
  DSH 已就绪（模式: ...）
```

**三行都出来 = 通了。**

---

## 第 7 步：端到端验证

**做什么**（按顺序，一步一确认）

| # | 动作 | 期望 |
|---|---|---|
| 1 | 用小号给自己的主号发一条消息 | 桥接日志出现「唤醒」 |
| 2 | 等 10~20 秒 | QQ 收到回复 |
| 3 | 问它"我们刚才说了什么" | 它能说出上一句 |
| 4 | 重启桥接，再问一次 | **还能说出来**（记忆落盘了） |
| 5 | 让它跑一条沙箱命令 | 能返回输出 |
| 6 | 看 `AI_data/.../short_term.json` | 有你的消息（role=用户） |

**第 4 步是最重要的**：重启之后还记得，才说明记忆真的落盘了，不是在上下文里。

## 常见故障

| 现象 | 最可能的原因 |
|---|---|
| 桥接连不上 DSH | DSH 端口变了；看 `dsh-client.js` 的发现逻辑 |
| 回复重复 | 换页阈值太低，或者没开去重 |
| **它记不住上一句** | 短期记忆没写进去 → 看 `short_term.json` 是否在长 |
| **记忆里出现奇怪的名字** | 身份标签取错了字段 → 看 `display_name()` |
| 召回很差 | 向量没跑起来（ollama 挂了会**静默失败**，不报错） |
| 沙箱没网 | iptables 顺序反了（DNS 在 10/8 里） |
| 沙箱能连宿主机 | 规则没加载，`[boot] command=` 没配 |

**两个"静默失败"要特别小心：**

1. **ollama 挂了** → 向量检索退化成词面检索，**不报错**，只是变笨
2. **日记写入没落盘** → 它自己感觉正常，但重启就忘

**这两个都不会给你报错，只会让你觉得"它今天有点傻"。**

---

## 最后：这一步之后会发生什么

**你会有一个人格化的 AI 在 QQ 上持续存在。**

**然后你会遇到我们遇到的所有问题**：
它的记忆会被污染、它的评测会自欺、它的"自我"可能是你给的。

**`docs/` 里那些坑，就是提前告诉你的。**
