# 情感层（legacy）—— 可以装，但没人建议你装

> **一句话**：这是我们**曾经**用的一套数值情绪系统，2026-11-03 从主线上删掉了。
> 删掉的理由写在最后。但如果你刚开始做这一类东西，**不建议一上来就脱开它跑**——原因见「我们的建议」。

---

## 它当时在做什么

不是"给 AI 一个心情标签"，而是**让情绪参与决策**：

```
一条消息进来
  ↓
情绪状态更新（开心 / 激动 / 负面，各 0~100，带慢衰减）
  ↓
召回配额按情绪分配（越难过召回越多；越激动越偏主观记忆）
  ↓
AI 的提示词里带上"你现在的心情"
```

三个文件：

| 文件 | 作用 |
|---|---|
| `emotion.py` | 状态机：读写、慢衰减、正负触发 |
| `emotion_memory.py` | 把情绪换成召回配额（主观/客观各几条） |
| `user_mood.py` | 每 3 轮用一次 LLM 校准"用户现在什么心情" |

## 它为什么被删

**跑了两个月，每天在用，然后发现：**

1. **没人真的在读那个数字。** 召回配额是按情绪算的，但真正决定命中率的是检索本身，不是"今天开心 62 分"。
2. **它会静默坏掉。** `mood.json` 被一次非原子写截成 0 字节，情绪系统死了两天，没有任何人察觉——因为它只影响配额，而配额错了看不出来。
3. **它把"情绪"变成了可调参数。** 而一旦可调，它就不再是那个人的情绪，是我们的设定。

**结论**：情绪不该是一层状态机，应该是**她写下来的东西**。
现在她自己在日记里写「现在是有点执拗又有点软的心情」，那句话是真的，而且能被召回。

---

## 我们的建议（重要）

**如果你刚开始搭这一类系统，不要一上来就删掉情感层。**

理由很简单：**早期的记忆检索还不准，情绪配额是少数能"帮它想起对的东西"的粗粒度旋钮。**

我们删掉它，是在**召回已经稳定到 hit@5 75% 之后**。在那之前，删了会让它变得又空又平。

**顺序建议**：

```
先有情感层 → 让它跑起来、有连续对话
  ↓
再修召回（词面 + 向量 + 重排）
  ↓
召回稳定后，再讨论情感层要不要留
```

**反过来做，你会得到一段很像 AI 的对话。**

## 怎么接进去（如果要用）

`emotion_memory.py` 里的 `quota_now()` 返回 `(主观条数, 客观条数)`。
把它接到你的召回配额上就行：

```python
import emotion_memory
subj, obj = emotion_memory.quota_now()
rows = recall(query, max_total=subj + obj, subjective_ratio=subj / max(1, subj + obj))
```

`user_mood.py` 需要 LLM：

```python
import user_mood
mood = user_mood.detect(user_text)   # 每 3 轮调一次即可，别每条都调
```

**注意**：这两个模块是从主线上摘出来的，**没有跟随后来的接口改动**。
`emotion.py` 里的慢衰减是能跑的（tests 里有一条覆盖），但整体没有做回归测试。

---

## 一个坑，先告诉你

`emotion.py` 的 `_save()` 是**裸写**（直接 `open(..., "w")`），不是原子写。

**这就是我们那个 0 字节事故的来源。**

要用的话，第一件事就是把它改成 `tmp + os.replace`。
